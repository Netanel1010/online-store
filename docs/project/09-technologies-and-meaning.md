# טכנולוגיות ומה הפרויקט מייצג

## 1. טכנולוגיות ושפות

הטבלאות כוללות רק מה שקיים בפועל ב-`main` (`package.json`, `server/package.json`, `render.yaml`,
`netlify.toml`, `.github/`). לכל טכנולוגיה נאמר מה תפקידה, למה נבחרה, ואם היא קיימת בייצור או ככלי בלבד.
כשהנימוק מתועד, מצוין מקורו. כשלא:
`Engineering rationale inferred from the implementation.`

### 1.4 מה היה ב-`L0` ואינו קיים עוד

HTML5, CSS3, JavaScript טהור (ES6), JSON ו-`localStorage` ללא שרת וללא בדיקות, Chatbase (הוסר ב-`T1`).
המצב נשמר בתיוג `legacy-v1`.

## 2. מה הפרויקט מייצג

השאלה: **מה אפשר ללמוד על היכולת ההנדסית של מי שבנה את הפרויקט רק מהסתכלות על התהליך והמערכת?**
התשובה מחולקת לפי נושאים. לכל נושא יש ראיה במאגר, מה היא מראה, ומה היא **לא** מוכיחה.

### 2.1 ממערכת צד לקוח למערכת full-stack

|                |                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ראיה**       | `L0` אתר סטטי ב-`localStorage`. `MS1`–`MS6` אתר React עם שירות נתונים מופרד. `BE` API ומסד. `SV` אימות. `M9` עגלה והזמנות בשרת. ראו [`05-project-history.md`](05-project-history.md) |
| **מה זה מראה** | מעבר מדורג בין ארכיטקטורות כשכל שלב נשען על הקודם. ה-`seam` ב-`productService` (#19) איפשר להחליף את מקור הנתונים בלי לשכתב דפים                                                     |
| **מגבלה**      | הקטלוג קטן (31 מוצרים). אין עדות לעומס או לגודל                                                                                                                                      |
